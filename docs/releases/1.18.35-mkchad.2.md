## Configurable V1 Compaction Ceiling

`compaction.max_tokens` is now an optional positive integer controlling the V1
automatic-compaction ceiling. Its default remains 180000 for existing users.
For a 360K ceiling, configure:

```jsonc
"compaction": {
  "auto": true,
  "prune": true,
  "max_tokens": 360000,
  "reserved": 20000,
  "preserve_recent_tokens": 8000
}
```

The effective threshold remains the smaller of the configured ceiling and the
existing natural model input/context-output threshold. This does not increase
a provider's actual context capacity. Disabled automatic compaction and unknown
context retain their existing behavior. Usage accounting and inclusive threshold
comparison are unchanged; invalid ceiling values fail configuration validation.
The V2 session implementation is unchanged.

When the recent-history budget is explicit, it remains independent of the
ceiling. When omitted, it is still derived from the usable threshold within the
existing 2000-15000 token bounds. Pruning and explicit manual compaction remain
available. Restart the OpenCode server after adopting the new configuration.

The configuration schema, generated JavaScript SDK Config type, and OpenAPI
Config schema include the new field. All other MkChad behavior from
[`1.18.35-mkchad.1`](1.18.35-mkchad.1.md) is retained.

## Native Rehearsal And Publication

Tag `rehearsal-v1.18.35-mkchad.2` exercises the native glibc Linux x64 and ARM64
builds, direct npm installation, exact version reporting, and managed-upgrade
refusal without creating a release. Publication must follow a successful
rehearsal at the same source commit, using tag `v1.18.35-mkchad.2`.

The publication workflow independently rebuilds both packages and verifies
the exact three-asset set, checksums, source tag, and GitHub immutability. Record
the completed run IDs, release identity, and published checksums with adoption
evidence. Source verification alone does not establish native build success,
published availability, live installation, container image adoption, or provider
capacity. The container pins and Schumann 360K configuration are maintained in
their independent repositories.
