## Upstream Improvements

This port includes the cumulative V1 changes from 1.18.30 through 1.18.35:

- Astra system prompt and Codex model admission for supported GPT-6 models.
- OpenAI/Azure SDK compatibility updates and preservation of explicit OpenAI
  service tiers through the upstream dependency patch.
- ACP durable model, effort, mode, and reasoning-boundary restoration fixes.
- Remote-config authentication diagnostics and failure exit status in the TUI.
- Credential and sensitive-header redaction in debug configuration output.
- Cloudflare Gateway timeouts and corrected Gemini thinking controls.
- Bedrock model-ID/media corrections, Together AI usage reporting, and xAI
  supported-image handling.
- Namespaced session and parent-session request headers, retaining legacy
  headers for existing integrations.
- Shared browser launching and detection of already-exited MCP launchers.

Upstream macOS signing and website changes remain in the source history; the
MkChad distribution contract remains glibc Linux x64/ARM64, not macOS packaging.

## Preserved MkChad Behavior

- Managed-upgrade refusal and direct Linux npm tarball packaging.
- Plugin compatibility against the upstream baseline while keeping the full
  managed version in diagnostics.
- Compound Engineering child-session task cards and role labels.
- Plugin metadata updates and native prompt-resolution support.
- Session admission, inspection, directory changes, context reload, guarded
  project reload, control APIs, and App/TUI reconciliation and recovery.
- Compatibility with V1 databases lacking the transitional context epoch table.
- The V1 180,000-accounted-token compaction ceiling, preserving lower natural
  thresholds and the existing reserve/accounting/disabled-auto behavior.

App and session-ui production source is unchanged from the previous fork.
The tracked compaction configuration changes remain in their independent
repositories; this port does not apply live configuration.

Five core npm-config tests initially failed because their empty directories
contained only `.npmrc`, allowing npm to discover an ancestor project. A narrow
reproduction confirmed that fixture-local `package.json` markers restore the
intended configuration. The fixture fix passed the affected npm tests and the
full core package without altering production npm configuration loading.
Release packer fixtures now use the caller's temporary directory, and explicit
`1.18.35-mkchad.1` tests cover both Linux target manifests, managed-upgrade
refusal, and upstream-baseline plugin admission/rejection.

Native artifact verification is separate from source verification; retain its
source/snapshot identity, artifact checksums, installation smoke, and
managed-upgrade refusal evidence with the release build. No published release,
remote branch/tag update, live deployment, service restart, container adoption,
or paid provider smoke is implied by this candidate.

Before remote publication, the candidate must be integrated into the protected
`mkchad` or `mkchad-v1` branch and pass the native x64 and ARM64 release workflow
with embedded web-client packaging and the normal immutable-release checks.

The existing release workflow takes its version from the operator-selected tag
and does not independently bind that version's upstream prefix to the source
manifest. This preexisting, non-blocking release-labeling risk was not changed
by the semantic port; use the exact reviewed `1.18.35-mkchad.1` version for this
candidate rather than an arbitrary upstream prefix.
